# Что исправлено и добавлено (по замечаниям заказчика)

## 1. «Невозможно создать задание, не продумано: куда название, куда варианты»
Старый экран просил только тему и количество вопросов, а варианты подставлялись
из случайного банка — учитель ничего не писал сам.

Сделано заново — `Контент → Новое задание`:

- **Шаг 1. Название и условия** — название (первое поле, сразу в фокусе), описание,
  тема, уровень, срок, код для учеников.
- **Шаг 2. Задания в варианте** — большая кнопка «Создать задание» → выбор типа,
  и форма открывается тут же, в этой же карточке. Никаких переходов между страницами.
- **Шаг 3. Проверка и публикация** — список «что осталось поправить» + предпросмотр
  «глазами ученика» + кнопка «Опубликовать».
- Черновик автоматически сохраняется: случайный уход со страницы работу не убивает.
- На телефоне внизу закреплена кнопка «Сохранить».

Шесть типов заданий, у каждого — своя форма:
один верный ответ, несколько верных ответов, вписать слово, аудирование (mp3),
карточки, развёрнутый ответ.

## 2. «Объединение нескольких заданий в один вариант»
Список заданий в редакторе и есть будущий вариант: можно создать задания с нуля,
взять готовые из библиотеки (`Взять из библиотеки`), продублировать, поменять
порядок стрелками и удалить. В одном варианте спокойно живут задания разных типов.
При сохранении каждое задание попадает в библиотеку и переиспользуется дальше.

## 3. «Объяснения и комментарии к каждому ответу»
- У **каждого варианта ответа** есть своё пояснение (раскрывается «+ пояснение к этому варианту»).
- У задания есть **общее объяснение**, которое ученик видит сразу после ответа.
- Встроенные задания Чистовика тоже показывают объяснение после ответа,
  а учитель может добавить **свой комментарий** к любому встроенному заданию
  (`Контент → Встроенные задания Чистовика → Комментарий учителя`).
  Комментарий виден ученику перед началом и на экране результата.

## 4. «Учитель создаёт сеты, все ученики их видят»
Появился полноценный конструктор набора слов (`Контент → Наборы слов → Новый набор`):

- таблица «слово — перевод — пример», необязательные категория/часть речи/определение;
- режим **«Быстрый ввод»**: вставили список строками `reloadable — надёжный` — слова добавились;
- счётчик слов, проверка перед сохранением, понятный блок «что получат ученики».

Наборы живут на сервере: ученик на любом устройстве видит наборы учителя
в разделе «Наборы слов» и в Lexis Lab (карточки, квиз, memory и т. д.).

## 5. Загрузка mp3
В любом задании есть блок «Загрузить mp3» (до 25 МБ): файл уходит на сервер,
ученик слушает его прямо в задании, аудио сохраняется в `server/data/uploads`.

## 14. Пятый заход: задание ≠ вариант
Раньше в «Контенте» была одна кнопка «Новое задание», которая на самом деле открывала
конструктор варианта, а форма любого типа выглядела почти одинаково. Развёл это по смыслу.

- **Две кнопки, два разных сценария.** «Создать задание» — одно упражнение, без кода,
  срока и списка. «Создать вариант» — несколько заданий вместе, с кодом, темой, сроком.
  Подписи внутри конструктора тоже приведены к «варианту» («Новый вариант», «Опубликовать вариант»).
- **Создание одного задания начинается с выбора типа** — шесть крупных карточек с примером
  («Впишите пропущенное слово: I have ___ been to London»). Дальше форма собирается
  ровно под этот тип, лишних полей нет.
- **У каждого типа своя форма:**
  | Тип | Что спрашиваем | Чего в форме нет |
  |---|---|---|
  | Один верный ответ | вопрос + варианты с одним кружком | полей пропуска и перевода |
  | Несколько верных | вопрос + галочки, можно несколько | кружка «один из» |
  | Вписать слово | предложение с `___` + список допустимых ответов | вариантов ответа |
  | Аудирование | сначала загрузка mp3, потом вопрос и варианты | текста «для чтения» по умолчанию |
  | Карточки | две стороны: слово / перевод | вариантов ответа и текста чтения |
  | Развёрнутый ответ | задание + критерии проверки | вариантов ответа |
- **Раздел «Отдельные задания»** — одиночные задания не смешиваются с вариантами:
  ученик видит их в «Библиотеке» и проходит сразу, учитель может изменить, пройти или удалить.
  Задание, добавленное в вариант, из этого раздела уходит (без дублей).
- Общие проверки вынесены в `taskIssues()` / `tidyTask()` в `src/data/content.ts` —
  одинаковые требования и в варианте, и в одиночном задании.

## 15. Шестой заход: почему «Нужен вход в аккаунт» при входе учителя
Это был не глюк платформы, а две настоящие ошибки — обе исправлены.

1. **Кабинет открывался без токена.** Старый вход выставлял роль сразу, а токен
   запрашивал «в фоне» и молча глотал ошибку (`catch(() => setToken(null))`).
   Если пароль не совпадал с паролем сервера — кабинет открывался, но каждая
   запись отвечала «Нужен вход в аккаунт». Теперь роль выставляется только после
   успешного ответа сервера, а неверный пароль показывается прямо на экране входа.
2. **Пароль учителя жил только в браузере.** «Регистрация» на экране входа
   сохраняла пароль в localStorage, а сервер о нём не знал. Теперь есть
   `POST /api/auth/teacher`: пароль (хеш scrypt) хранится на сервере, и вход
   принимает либо пароль из настроек сервера, либо ваш собственный. Сменить его
   можно в «Настройках» → «Пароль входа».

Что ещё поправил по ходу:
- **Ключ подписи токенов вынесен в `server/data/secret.txt`.** Раньше он лежал в
  `db.json`: любая пересборка базы обнуляла все входы, и залогиненный учитель
  получал «Нужен вход». Проверено: токен живёт после перезапуска сервера.
- **Страховка от протухшей сессии.** При ответе 401 клиент один раз пробует
  восстановить гостевую сессию ученика по имени. Ученическая учётная запись
  восстанавливается через вход по почте и паролю; учителю нужен пароль.
  Если восстановить сессию нельзя — показывается понятный экран входа с текстом
  «Сессия истекла — войдите ещё раз, данные на сервере целы». Сетевая ошибка
  не считается истёкшей сессией: пользователь остаётся в кабинете.
- **Сайт работает даже там, где браузер запрещает localStorage** (окно
  предпросмотра в песочнице): хранилище `src/lib/storage.ts` падает обратно
  в память. Вход и сохранения работают, а сверху честная плашка «браузер не даёт
  сохранить вход» с кнопкой «Открыть в новой вкладке».
- **Нет связи с сервером** — отдельная плашка вместо тихих ошибок: видно, что
  показаны локальные данные и новые сохранения не уйдут.
- После восстановления из копии и сброса данных страница по-прежнему
  перезагружается — это осознанные действия, а не самопроизвольные перезапуски.

## Как проверить (5 минут)
1. `npm run dev:all`
2. Войти как учитель: `admin@chistovik.app` / `english2026`. Если браузер помнит
   старую сессию, сайт один раз попросит войти заново — это ожидаемо.

   Затем «Создать вариант» → «Добавить задание» → «Карточки» → слово и перевод → «Опубликовать вариант».
4. Выйти, войти как ученик (или открыть лендинг и ввести код) → пройти задание →
   увидеть объяснение после ответа.
5. «Программа»: переименовать сет → перезагрузить страницу → изменение на месте;
   зайти учеником на другом устройстве — название то же (программа живёт на сервере).
6. «Контент» → «Наборы слов» → «Новый набор» → «Быстрый ввод» → вставить 5 строк →
   «Создать набор» → ученик видит набор в Lexis Lab.
7. Проверка: создать задание типа «Развёрнутый ответ», пройти его учеником,
   зайти учителем в «Проверка» → поставить балл и комментарий → у ученика
   на главной появится «Слово преподавателя».

## 16. Седьмой заход: гостевой офлайн, аккаунт ученика и строгий UX
- **Исправлен выброс учителя из кабинета без сети.** Раньше сетевой сбой во время
  `me()` распознавался как истёкший токен. Теперь только настоящий 401 ведёт
  к повторному входу; отказ сети оставляет текущую роль и показывает честную
  плашку «Нет связи с сервером». Проверено отдельно для учителя и ученика.
- **Добавлен настоящий аккаунт ученика.** Регистрация по имени, почте и паролю
  хранится на сервере (scrypt); можно войти на другом устройстве. Гостевой вход
  без регистрации сохранён. Аккаунт нельзя открыть простым гостевым входом по
  совпавшему имени; пароль не хранится в localStorage и не выдаётся в списке
  учеников. API-проверка: создание 201, правильный пароль 200, неверный 401,
  гостевой обход аккаунта 401, хеш не попадает в `/api/students`.
- **Добавление ученика преподавателем** больше не требует скрытый email; имя
  обязательно, а пустое имя даёт явную подсказку.
- У gap-задания ответы теперь набираются в черновике и добавляются Enter или
  отдельной кнопкой; повторяющиеся варианты блокируются. Проверено, что ввод
  `live`, `lived` сохраняет оба ответа, а ввод без Enter не создаёт символы.
- Сохранение пустого названия программы отключено, действия переименования
  модулей доступны по клавиатурному имени и кнопкам screen reader; при проверке
  переименование синхронизировалось и отобразилось у ученика.
- Удаление варианта подписано именно «Удалить вариант».
- Повторный свип: 11 экранов (лендинг, 6 учительских, 5 ученических),
  0 ошибок консоли и пустых экранов. Офлайн-тест: обе роли остаются в кабинете,
  предупреждение показано, 401 ведёт к входу; 0 ошибок консоли.
- Учётная запись ученика прошла UI-проверку регистрации и входа в чистом
  хранилище другого браузера; учётные данные не остаются в localStorage.
- После аудиторских прогонов восстановлены демо-данные: 3 задания, вариант
  `TASK-101`, 1 набор слов, 12 сетов программы; тестовые задания и сдачи удалены.
- Финальная проверка: `npx tsc --noEmit` и `npm run build` успешны; single-file
  сборка `dist/index.html` — 4,344.26 kB (gzip 2,855.78 kB).

Примечание к тестам: браузерный Chromium в этой среде недоступен, поэтому
поведенческие прогоны выполнены на jsdom; два отдельных тестовых сценария
использовали некорректные селекторы (проверка комментария до выполнения
проверяемой сдачи и поиск кнопки «Пропустить» вне реального гостевого маршрута).
Это ошибки тестового сценария, а не продукта; гостевой маршрут проверен отдельно.

## 17. Восьмой заход: таймеры, «Трио» и безопасное редактирование программы
- В задании теперь можно задать **необязательный таймер на задание** (в минутах).
  По истечении ответ блокируется и показывается, что время вышло; частичный
  развёрнутый ответ сохраняется для ручной проверки.
- В конструкторе варианта добавлен **необязательный общий таймер**. После
  истечения оставшиеся вопросы отправляются без ответа, вариант автоматически
  завершается. Время видно ученику как `мин:сек`; последние 30 секунд выделены.
  Оба режима сохраняются на сервере и работают также при прохождении одиночного
  задания (таймер задания).
- Добавлен формат **«Трио — общий глагол»**: учитель вводит ровно три предложения
  с маркером `___` и один точный общий глагол. Ученик вписывает его один раз;
  введённое слово отображается во всех трёх фразах. Проверяются все три маркера,
  один ответ и объяснение; формат доступен и в одиночном задании, и в варианте.
- У модулей появилась отдельная, подписанная кнопка удаления и явный шаг
  подтверждения; удаление убирает модуль из текущего сета, не удаляя уроки из
  библиотеки. Удаление темы вынесено из кликабельной строки урока в отдельную
  большую кнопку. Строка урока теперь содержит отдельную кнопку открытия —
  нажатие «Удалить тему» не открывает само занятие.
- Подсветка выбранного/текущего месяца сделана светлой тёплой, с контрастной
  обводкой вместо визуально тяжёлой тёмной заливки.
- Проверка: API roundtrip и серверная валидация формата «Трио»; верный ответ
  прошёл UI-проверку; общий и отдельный таймеры отработали; удаление модуля и
  темы проверено без случайного открытия урока; 0 ошибок консоли. `npx tsc
